## Вопрос

Два телефона, Node-сервер (локально или на Hetzner), архитектура из 001 поверх прототипа 010: видим друг друга, прыгаем, толкаемся. Пользователь с другом по Discord проверяют, терпима ли задержка. Выход: go/no-go по архитектуре и tick rate; если no-go — что менять (вплоть до отказа от платформера в пользу вида сверху).

## Резолюция

**GO: онлайн-платформер играбелен.** Прототип: https://leksar.github.io/krysy-krysyat/proto/011/ ↔ `wss://89-167-106-105.sslip.io/krysy/ws` (сервер на Hetzner, за council-caddy). Пользователь с другом играли с телефонов: пинг ~47 мс, «лаг ушёл, играть можно».

- Архитектура подтверждена: server-authoritative, общий `packages/sim` (60 Гц, AABB), предсказание своей Крысы с переигрыванием неподтверждённых инпутов, интерполяция чужих с задержкой 100 мс, снапшоты 30 Гц. Коррекции — единицы пикселей, заметны только при укусе (внешнее воздействие — ожидаемо).
- Транспорт — простой `ws` + JSON вместо Colyseus: ~150 строк сервера хватило; Colyseus остаётся опцией, когда понадобятся комнаты/реконнект/матчмейкинг (тикет 014).
- Найденный и исправленный баг: сервер не отсеивал повторно присланные инпуты против уже стоящих в очереди → очередь росла ×5, упиралась в лимит, терялся хвост → ~1 с задержки при хорошем пинге. Урок: дедуп инпутов — против самого нового известного seq; `/health` отдаёт длины очередей и tps для диагностики.
- Сеть на телефоне: 60 fps на Pages-странице, ~20 КБ/мин трафика на клиента при 3 крысах.
- Инфраструктура, поднятая по ходу (тикет 012 исполнен): `/opt/krysy` на Hetzner, образ `ghcr.io/leksar/krysy-server`, деплой из GitHub Actions ключом с принудительной командой, маршрут `/krysy*` через `import` в Caddyfile council (PR #19, #20 в leksar/council).
